# 环视大图审核

在一张大图上审核整个场景，减少在来源视图间来回切换。网页默认显示环视大图，原有高清来源审核保留在下方的折叠区域。

## 操作

1. 滚轮或 `＋ / −` 放大缩小，拖动平移；“显示全图”恢复整个场景。“展开大图”扩大工作区。
2. 点击候选，右侧直接显示它在高清来源图中的裁剪，可确认或排除。Ctrl / Shift 点击可多选，也可用“框选多个”拖框，然后统一确认或排除。
3. 用“只看待审”减少干扰，“显示已排除”可找到并恢复误操作的候选。审核动作保留原始证据和仪表编号。
4. 漏检时选择“补充漏检”，在大图拖框。页面自动列出覆盖该区域的高清来源，先核对蓝框；有偏差时直接在来源图重画，或选择另一个来源。保存后成为待审候选，再确认需要采集的仪表。

补框不要求操作员先找出第几张扫描图。它仍保留一次高清来源核对，因为环视图具有拼接缝、视差和近似位置误差；这能避免误把背景裁剪绑定到仪表。大图放大使用现有预览像素，高清细节由右侧来源裁剪或补框对话框提供。

## 数据与限制

当前交互式补框支持带有 `ring_projection` 的角度辅助圆柱预览。对于未建立来源映射的旧总览，仍可展开高清来源补框，不凭空推算坐标。CLI 可通过 `Store.bind_overview_geometry` 将**该预览实际使用的已保存渲染参数**关联到原图，严格核对预览哈希、尺寸、来源顺序、图像哈希、方向和固定俯仰/倍率；不根据一个任意焦距宣称已标定。

`/api/overview/sources` 仅提出可能的高清来源，不修改清单。`/api/candidates/from-overview` 在明确核对来源后保存人工框与关联证据；新候选的检测分数为空，不伪装成模型输出。大图框、最初映射框及人工修正后的来源框分别保存。后续修正来源框时，旧人工记录保留，显示位置重新估计。

`/api/review/many` 在同一个版本检查和事务中处理 1～100 个同场景候选。任一操作不满足条件，整批回滚；旧版本请求返回冲突，避免部分成功或覆盖他人的选择。已有仪表编号可保留，排除时禁用采集而不删除历史图像。

这些入口只修改审核资料。不会启动扫描、转动云台、验证回访位置、生成读数或启用周期任务。

## 检查

```bash
python -m unittest discover -s src/inspection_console -p 'test_*.py'
node scripts/test_overview_ui.js
node --check src/inspection_console/overview.js
```

Python 检查覆盖补框来源绑定、状态保全、批量事务、版本冲突、HTTP 权限和无硬件模式。Node 检查覆盖缩放坐标、边界、反向框选、页面元素以及异步数据返回前的启动；这些检查不替代真实浏览器交互验收。
