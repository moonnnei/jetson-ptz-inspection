# 系统架构与数据约定

[项目首页](../README.md) · [审核控制台](REVIEW_CONSOLE.md) · [回访参考](REVISIT_REFERENCE.md) · [开发路线](ROADMAP.md)

## 运行边界

| 模块 | 部署位置 | 输入 / 输出 | 当前设备行为 |
| --- | --- | --- | --- |
| RTSP 采集与通用检测 | TX2 | 视频 → 最新帧、框、分数、帧序号 | 读取视频 |
| 有限扫描 CLI | TX2 | 已准备计划 → 高清原图、姿态与记录 | 默认只读；显式执行后有界运动 |
| 场景建图与候选发现 | PC | 原图 → 配准/投影预览、来源候选 | 不连接相机 |
| 审核控制台 | PC 或 TX2 | 候选 → 人工清单、稳定编号、参考计划 | `NoHardware`，周期执行关闭 |
| 旧巡检 Demo | TX2 | 人体观测 → 扫描/居中/变焦/留图 | 独立运动入口，已有限定实机结果 |

现有模块通过文件清单和受校验的导入衔接，尚无开机全自动流水线。相同相机的运动入口共享 Linux 进程锁；网页审核不会调用旧 Demo 作为隐式回访控制器。

## 图像与坐标

- 原始来源图和全景图以 SHA-256 标识，图像方向、尺寸及来源姿态一起保存。
- 候选框为对应来源图上的 `[x1,y1,x2,y2]` 像素坐标。旋转时图像和框必须同步变换；原始字节与哈希继续保留。
- 局部平面总览可带 `to_overview` 单应矩阵。环视柱面投影为非线性映射，不伪造平面单应矩阵。
- 全景跨接缝框在显示时拆段；图像左右相邻不代表云台机械轴可跨越零点。
- 当前型号配置使用水平 0～350°、俯仰 0～90°、倍率 1～2；不同设备必须重新核对能力与控制单位。
- 全景坐标只支持近似图像关联；未验证为像素到云台运动的标定。

## 三种位置不能混用

1. **来源姿态**：历史视图拍摄时的 pan/tilt/zoom，可能同时看到多块表盘。
2. **搜索位置**：后续用于较宽视野重新寻找指定仪表的位置，仍待实机教学。
3. **采集位置**：指定仪表已居中、倍率合适并通过新图验证的位置。当前真实仪表 `visit_pose` 尚未验证。

人工确认只创建仪表档案，不会把来源姿态复制成已验证采集位置。地图失效、人工框变化或重启恢复不能沿用未经检查的运动计划。

## 存储与一致性

SQLite 保存版本化清单和追加式审核日志，图片存于独立内容寻址目录。所有修改对照整数修订号，并在单个事务中完成；网页遇到旧版本返回冲突，不覆盖另一人的修改。

候选可确认、排除、恢复、补框、修正和合并。仪表编号稳定，不通过删除或复用编号掩盖历史。来源图原图裁剪只是审核预览，不能当作新拍摄近景。

`/api/state` 可计算临时全景显示框，`/api/export` 保留原始存储内容，不导出控制令牌。导入源文件由本地 CLI 读取，网页不接受任意文件系统路径。默认只监听 loopback；局域网部署需要显式允许本机 Host。控制令牌防跨站请求，不构成用户登录认证。

## 实机周期回访的后续接入

计划由 TX2 调度：读取已确认且启用的仪表 → 按可执行路径访问 → 到位后检查最新图像 → 身份/局部位置复核 → 视觉微调和变焦 → 图像质量验收 → 保存新图及状态。失败必须记录为失败，不能填入旧图或假读数。

现有调度器已覆盖固定延迟、禁止重叠、取消和重启暂停等逻辑。当前 `NoHardware` 拒绝物理启用；需要实际适配器、经验证的采集位置和真实仪表单轮验收后才可启用。读数模型由外部算法模块提供，本工程负责接口与部署。
