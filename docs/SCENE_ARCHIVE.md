# 场景档案与数据保留

新建场景会增加一个独立场景，不覆盖原全景、原始扫描帧、审核清单、仪表名称、采集位置或历史照片。照片按内容哈希保存，采集任务归档在同一数据库的 `job_history` 中。结果展示按场景 ID 与仪表 ID 隔离，新的场景不会直接继承旧场景的照片作为本轮成功图。

## 找回旧场景

工作台的“场景档案”下拉列表显示各场景的编号、上海时间建档时间和已登记仪表数，最新场景排在前面。选旧场景后可查看其全景、清单和采集结果。浏览器会记住此次选择；刷新后仍打开该场景。主动开始一次新扫描后，页面跟随本次新场景；手动选择档案即可退出跟随。

“查看此场景采集记录”直接打开对应历史结果。历史结果还提供独立的“历史场景”筛选，可以保持当前工作场景不变，仅查看其他场景的照片；再按日期、轮次查看。空场景显示没有历史轮次，不借用其他场景的照片。

以上选择和浏览操作只读取资料，不移动相机或启用周期采集。实时监看始终显示相机此刻的画面，不会因为查看历史照片而回放旧画面。浏览器存储不可用时，选择仍可在当前页面使用；刷新后默认显示最新场景。

## 保留边界

- 新扫描、扫描失败及程序重新打开后，旧场景记录继续保留。新扫描会取消原来暂停的未完成建档队列，已有观测和任务记录不会删除。
- 当前原型最多保存 20 个场景。达到容量时拒绝新建并提示，不自动淘汰旧场景。
- 周期调度仍只有一个活动配置。浏览场景不会恢复或启用旧周期任务；重新执行需使用明确的采集入口。切换档案不证明相机或仪表仍在原位置。
- “导出清单”导出元数据，不包含照片字节。迁移或备份需要同时保留数据库和 `images/`，不能只复制 JSON。
- 结果区的原图和裁剪图使用实际拍摄时间；历史失败轮次不由其他轮次补成成功。超分和数值读数未接入。

node scripts/test_results_model.js

node scripts/test_scene_navigation_ui.js
python -m unittest discover -s src/inspection_console -p test_scene_initialization.py -v

检查覆盖新场景成功和失败后的旧数据保留、重新打开数据库、容量满时不淘汰、刷新后记住场景、显式扫描跟随、独立历史场景筛选、跨场景隔离，以及名称输入焦点不能阻止场景切换。网页检查执行实际生产函数并使用 DOM 契约替身，不等同于浏览器视觉验收。

2026-10-24 的现场只读检查中，数据库中仍有 15 个场景、97 条已归档任务；记录引用的 412 张照片全部存在且内容哈希一致。该结果解释了本次用户反馈：新建后页面切到新场景造成旧资料难以找到，未发现这些记录或照片被物理删除。这不是对未来所有硬件故障的数据恢复保证。
