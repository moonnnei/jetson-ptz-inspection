# 有限轮次巡检与执行统计

[项目首页](../README.md) · [预置位采图](SOFTWARE_PRESET_PATROL.md)

固定位置完成建档后，可以在网页设置巡检间隔和最多运行轮数。轮数留空为持续运行；填写 1～1000 的整数时，TX2 在完成指定轮数后自动停止。每轮结束后才开始计算等待间隔，不叠加任务。启动服务不启用周期，重新启用会建立新的批次并从零计数。

## 操作与结果

1. 确认当前场景清单和预置位就绪。
2. 保存间隔及可选轮数，再点击启用。
3. 网页显示本批完成轮数，历史记录显示每轮耗时、成功留图数、新拍张数、质量拒绝数和通过观测数。
4. 达到上限后显示“本批次已完成，已自动停止”。出现不确定、故障、主动停止或重启时保持暂停，不将不完整轮次计为成功。

运行中的批次不能重复启用来重置计数；需要先停止。单轮采集独立于周期，不会增加旧批次计数，也不会开启新的周期。主动停止可能保留诊断图，不能将这些图冒充已完成的逐表采集。

## 接口兼容

```json
{
  "revision": 123,
  "map_id": "YOUR_MAP_ID",
  "interval_seconds": 60,
  "round_limit": 5
}
```

上述 JSON 用于既有 `POST /api/schedule/configure`，仍需同源控制令牌。旧客户端省略 `round_limit` 等价于 `null`，保持持续周期语义。配置保存后不自动启用；通过既有 `/api/schedule/arm` 启用。允许间隔为 60～86400 秒。

`schedule` 新增 `batch_id`、`round_limit`、`attempted_rounds`、`completed_rounds`。每个周期任务保存所属批次、轮次索引和当次上限。成功轮数仅在整轮完成、停止已确认之后持久增加；达到上限时清除下一执行时间并关闭周期。

## 统计含义

| 字段 | 含义 |
| --- | --- |
| `elapsed_seconds` | 调度工作线程的单调时钟耗时，不含此前等待间隔 |
| `metrics.captured / targets` | 本轮成功留图的仪表数与目标数 |
| `metrics.fresh_capture_requests` | 实际新抓图次数，包含未通过的诊断图和追加拍摄 |
| `metrics.quality_checks / rejections / passes` | 当次基本质量检查及通过/拒绝数量 |
| `metrics.capture_elapsed_seconds` | 底层有限采集控制器耗时 |
| `metrics.stop_confirmed` | 软件与相机接口的 STOP 确认；不是物理拔网线实验 |
| `metrics.returned_pose` | 正常返回姿态；取消或异常时可为空，不自动追加返回动作 |

统计失败不会阻止任务结束和暂停。图像质量阈值保持原策略；这些字段不证明数值可读性、全场景发现准确率或长期稳定性。

## 验证边界

针对性检查覆盖轮数上限、旧客户端、重复启用、失败与取消计数、重启暂停、独立单轮、统计异常，以及真实采集适配器取消时的异常传播。完整 PC 标准库检查 471 项（470 通过、1 项 Windows 平台跳过）。

已完成一次真实途中停止：第一张新图之后发出 STOP，约 1.315 秒完成接口停止与工作线程退出，随后无新增采图或任务重放。随后重新启动五轮批次，全部完成，20/20 次逐表采集与 40 次新图身份/质量通过观测；实际新拍 46 张，其中 6 张相对模糊而拒绝，有限补拍后恢复。质量阈值未放宽。

| 轮次 | 底层采集耗时 | 新拍张数 | 质量拒绝 | 逐表成功 |
| --- | ---: | ---: | ---: | --- |
| 1 | 112.413 秒 | 9 | 1 | 4/4 |
| 2 | 113.503 秒 | 9 | 1 | 4/4 |
| 3 | 113.442 秒 | 9 | 1 | 4/4 |
| 4 | 117.846 秒 | 10 | 2 | 4/4 |
| 5 | 115.422 秒 | 9 | 1 | 4/4 |

第五轮后由 TX2 自行转为 `batch_completed`、关闭周期并清除下一次执行时间，观察程序在成功路径没有调用停止接口。再观察 65 秒，数据库修订 263 保持不变，没有启动第六轮。整组含四次 60 秒间隔和最后观察共 884.000 秒。该组是同一四表现场的短时稳定性验证，不代替跨天或陌生环境验收。
